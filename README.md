# Qsecret · 本地密码保险库

一个只跑在本机的密码管理器：全部条目加密后存在一个文件里，浏览器界面操作，**零第三方依赖**（只用 Node.js 内置模块），不联网、无遥测、无云同步。

```
主密码 ──scrypt──► 主密钥 ──HKDF──► encKey / macKey / verKey
                                      │        │        │
                            每条 AES-256-GCM  文件 HMAC  密码校验哨兵
```

## 快速开始

要求：macOS（也可用于 Linux/Windows）+ Node.js 18 或更高版本。

```bash
# 方式一：双击 start.command（会自动找 Node、启动服务并打开浏览器；关窗口即停止）

# 方式二：命令行
node server.js

# 方式三：后台服务，登录系统后自动启动（macOS，推荐日常使用）
bash service/install.command      # 或双击 service/install.command
bash service/uninstall.command    # 卸载：只移除自启项，不删数据

# 指定端口 / 数据目录
QSECRET_PORT=9000 QSECRET_DATA=~/my-vault node server.js
```

默认地址：<http://127.0.0.1:7878>

> 如果 `node -v` 显示低于 18（本机 `/usr/local/bin/node` 可能是旧版），直接用 `start.command` 或安装后台服务即可，两者都会自动挑一个 18+ 的 Node。服务端也有版本检查，版本不足会明确报错而不是诡异崩溃。

首次打开会引导你设置主密码。**主密码不会被保存，忘记即永久失去全部数据**，请用 4 个以上不相关单词组成的长口令，并单独记牢。

界面上没有看明白的地方，点右上角「手册」——完整的使用手册做在了界面里（锁定页底部和设置页也有入口）。

## 后台服务（开机自启）

`service/install.command` 会做三件事：

1. 把应用复制到 `~/Applications/Qsecret`（可用 `QSECRET_HOME` 改路径；不会覆盖那里已有的 `data/`）。
2. 在 `~/Library/LaunchAgents/com.qsecret.vault.plist` 注册用户级 LaunchAgent：登录后自动启动、进程意外退出自动拉起。
3. 启动并确认 `http://127.0.0.1:7878` 可访问。

| 项目 | 说明 |
| --- | --- |
| 自启时机 | 用户登录之后（不是开机、未登录时）。密码库需要你登录后再输主密码，这是更合适的时机 |
| 崩溃恢复 | `KeepAlive`，退出后由 launchd 拉起 |
| 端口冲突 | 服务模式下手动的实例还在跑时，服务不抢端口、不退出，等对方退出后自动接管 |
| 日志 | `~/Library/Logs/qsecret.log`、`~/Library/Logs/qsecret.error.log`（不含密码和条目内容） |
| 与 start.command | 服务已在运行时双击 `start.command` 只会打开浏览器，不会重复启动 |
| Node 路径 | 安装时写死一个 Node 18+ 的绝对路径；卸载或升级该 Node 后请重新运行一次安装脚本 |
| 卸载 | `service/uninstall.command`：停止进程、把 plist 移到废纸篓，应用和数据原地保留 |

**服务常驻 ≠ 已解锁。** 服务启动后保险库仍是锁定状态，每次打开都要输入主密码；空闲与绝对超时照常生效。

## 安全设计

### 密钥与加密

| 环节 | 实现 |
| --- | --- |
| 主密码 → 主密钥 | `scrypt(N=131072, r=8, p=1, salt=16B 随机)`，单次约 128 MiB 内存、0.3–1 秒 |
| 密钥分离 | `HKDF-SHA256(masterKey, salt, info)` 派生 `enc` / `mac` / `verify` 三把 256-bit 子密钥，互不通用 |
| 条目加密 | AES-256-GCM，每条独立随机 96-bit IV；AAD 绑定 `vaultId + 条目 id + 版本号`，防止密文挪用与回滚 |
| 文件完整性 | HMAC-SHA256 覆盖 KDF 参数、校验块、全部条目密文与元数据；删条目、改顺序、改头部都会被拒绝打开 |
| 主密码校验 | 不保存密码哈希，改为加密固定哨兵；解密失败即密码错误，比较使用 `timingSafeEqual` |
| 换主密码 | 重新生成盐并派生新密钥，逐条解密→重新加密；旧密钥立即抹零 |

KDF 参数写在文件头里，`KDF_DEFAULT` 只影响新建的库；以后提高成本不会破坏旧文件（旧文件按自己的参数解锁）。

### 运行时会话

- 服务只监听 `127.0.0.1`，不接受外部连接。
- 校验 `Host` 头必须是 `127.0.0.1:端口` 或 `localhost:端口`，阻断 DNS rebinding。
- 会话 Cookie：`HttpOnly; SameSite=Strict; Path=/`；CSRF 令牌放在请求头，写操作强制校验。
- `Origin` / `Sec-Fetch-Site` 不是同源一律拒绝。
- 严格 CSP：`default-src 'none'`，脚本/样式仅同源，无内联、无外部 CDN、无 `eval`。
- 密钥只存在于进程内存；锁定、空闲超时（默认 5 分钟）、绝对超时（8 小时）、退出进程都会抹零。
- 解锁失败指数退避：第 5 次起 60 秒，之后每次翻倍，上限 1 小时；计数写入 `auth-state.json`，**重启也绕不过**。
- 不记录请求体、密码、条目内容；日志只有启动、加锁、创建库等事件。

### 落盘

- `data/vault.qvault` 权限 `0600`，写入采用「临时文件 + fsync + rename」原子替换，并保留上一版 `.bak`。
- 文件里只有 KDF 参数、盐、版本号和密文；标题、账号、密码、备注均为密文。
- 备份接口导出的就是该密文文件，泄露备份但没有主密码同样无法解密。

## 威胁模型（请如实理解）

**能有效防护：**

- 电脑丢失、磁盘/备份文件被拷走 → 没有主密码只能硬碰 scrypt，成本极高。
- 有人篡改保险库文件（改密文、删条目、降 KDF 参数）→ 校验失败，拒绝打开。
- 恶意网页跨站调用本地接口、DNS rebinding、CSRF → 被 Host/Origin/CSRF/CSP 拦下。
- 密码明文被写进磁盘或日志 → 不会发生。
- 短暂离开电脑 → 自动锁定。

**不能防护（任何本机密码管理器都做不到）：**

- 电脑已被植入木马、键盘记录器、屏幕录制或 RAT —— 主密码输入时就会被截获。
- 恶意浏览器扩展读取页面 DOM —— 明文显示在页面上时扩展能看到。
- 拥有你系统账户并能读取进程内存的攻击者（同用户权限即可 dump 内存）。
- 你忘记主密码 —— 设计上没有后门，无法恢复。
- 肩窥、剪贴板被其他程序读取、密码被粘贴到不安全的地方。
- 供应链之外的问题：本工具为个人项目，**未经过第三方安全审计**，不建议直接用于高价值生产凭据。

## 数据、备份与迁移

```
qsecret/                   仓库目录；装成后台服务后运行的是 ~/Applications/Qsecret 里的副本
├── server.js            本地 HTTP 服务
├── lib/crypto.js        加密内核
├── lib/vault.js         存储与条目逻辑
├── public/              界面（HTML/CSS/JS，无外部资源，含内置使用手册）
├── service/
│   ├── install.command  注册 macOS LaunchAgent（登录自启）
│   └── uninstall.command
├── data/                运行时生成（已被 .gitignore 忽略）
│   ├── vault.qvault     加密保险库（0600）
│   ├── vault.qvault.bak 上一版自动备份
│   └── auth-state.json  失败计数与锁定时间
├── test/                自检脚本
└── start.command        双击启动（手动模式）
```

数据文件在**运行中的那份应用目录**下的 `data/`：手动启动是仓库目录，后台服务是 `~/Applications/Qsecret/data/`。

- **备份**：设置 → 下载加密备份，得到 `qsecret-backup-YYYY-MM-DD.qvault`。可与主密码分开存放（例如备份放网盘、主密码记在纸上）。
- **恢复**：设置 → 填写该备份的主密码 → 选择 `.qvault` 文件 → 覆盖当前库（系统会另存一份 `.bak`）。
- **迁移电脑**：整个目录拷走，或在新机器建库后用备份恢复。
- **多设备**：不做自动同步。手动同步备份文件时注意「后写覆盖」，可能丢失另一端的改动。

## 忘记主密码怎么办

没有找回机制。`data/vault.qvault` 里的数据在密码学上无法解开；只能删除该文件重新创建（等于放弃旧数据）。这是「主密码不落盘」的必然代价。

## 自检

```bash
node test/crypto.test.js   # 加密内核：往返、错密码、篡改、换钥、备份、设置
node test/api.test.js      # 真实起服务：鉴权、CSRF、跨站、限速、静态资源、恢复
```

当前结果：内核 18 项、接口 25 项全部通过（接口层含"服务模式端口被占时等待并接管"）。界面另外用无头浏览器实跑过 21 项：建库 → 建条目 → 手册入口（锁定页 / 顶栏 / 设置页）→ 目录跳转与滚动高亮 → 移动端布局 → 无控制台报错与 CSP 拦截。

自检只在临时目录创建测试保险库，不会碰你的真实数据。

## 已知边界

- 单用户、单活跃会话：新解锁会让旧会话失效（设计如此）。
- 没有 TOTP、自动填充、浏览器扩展、团队共享。
- 没有审计日志（避免日志本身成为泄露面）。
- 剪贴板清除依赖浏览器权限，属于尽力而为。
- 端口固定时若被占用，启动器会提示；可用 `QSECRET_PORT` 换端口。
- 后台服务目前只提供 macOS（launchd）脚本；Linux 的 systemd、Windows 的计划任务需要自行配置，启动命令都一样：`node server.js`。
- 仓库改了代码后，后台服务跑的仍是 `~/Applications/Qsecret` 里的旧副本，需要重新运行一次 `service/install.command` 同步。
